# 向老師展示的流程

[回專案首頁](../README.md)

展示應讓老師能連結「研究問題、系統處理方式、實際操作、評測證據」。可先以這四項為主線，再依提問開啟對應程式。

## 展示前準備

準備一個已核准教師帳號、一個學生帳號、一份有權使用的文字型 PDF，以及兩個可回到原始教材確認的問題。檢查網站、教材檢索、模型和語音服務；記錄當日 commit、build、模型與環境。

離線檢查可先執行 `python3 scripts/check_offline.py`。真實問答與裝置語音仍需另外操作確認。

## 建議順序

| 順序 | 展示內容 | 同時可提供的依據 |
|---|---|---|
| 1 | 首頁：系統處理什麼教學情境、有哪些模組 | README 與系統架構 |
| 2 | 教師上傳 PDF、確認章節、查看準備狀態 | `course_runtime.py`、課程 manifest |
| 3 | 選定同一章節播放講稿 | 教材原文、講稿與章節名稱對照 |
| 4 | 用教材能支持的問題做 Q&A，查看回答來源 | question、context／sources、模型與耗時 |
| 5 | 抽題、跳題、保留選項並完成作答 | `exam_questions.py`、quiz navigation 驗證 |
| 6 | 呼吸生理課程中調整 V/Q 參數 | 數值引擎、守恆驗證與參考比較 |
| 7 | 學生以課程代碼加入、查看可用操作 | `access_control.py` 與權限流程 |
| 8 | 開啟逐題模型結果，說明 accuracy 與等待時間 | 原始結果檔、資料集與評分定義 |

## 常見提問與應出示的資料

| 老師可能問 | 回答時的依據 |
|---|---|
| 為什麼需要這個系統？ | 說明實際觀察的教材問答與教學操作問題，再對應本研究評估的正確率、耗時與功能 |
| 回答從哪裡來？ | 出示當次檢索段落、來源與模型回答，區分向量檢索及文字備援 |
| 上傳的科目改變，系統怎麼處理？ | 課程工作區、章節與獨立索引；另外說明跨學科表現尚需評估 |
| 怎麼知道答案正確？ | 答案鍵、來源、評分規則與逐題記錄；模型審查是系統處理的一部分 |
| 系統快不快？ | 指定起訖點的實測時間、模型、硬體、warm-up 與失敗請求 |
| 有沒有測試？ | 展示此次實際執行的檢查結果，並說明覆蓋範圍 |
| 哪裡是你修改的？ | 功能對照程式、真實 commit diff 與修改前後的行為 |
| 為什麼很多檔案都是 Initial commit？ | 初次把既有專案匯入 GitHub；後續從實際修改開始累積歷程 |

## 每次展示留下的最小紀錄

記下日期、commit SHA、模型 ID、教材／題集版本、操作步驟、預期結果、實際結果及問題。遇到無法回答的題目，保存該次 evidence 和回覆，作為下一次修正與回歸檢查的依據。

若尚無正式教學成效資料，可把已完成的成果界定為系統開發與技術表現評估，並清楚說明後續要驗證的問題。
