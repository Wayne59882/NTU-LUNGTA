# v241.10：自訂題數、交卷統計、課程刪除與回報辨識

## 這次改了什麼

- **情境題如何產生**：上傳課程後，程式從每個已選單元的可讀教材句子，快速整理出 100 個不重複的來源知識點。這些知識點尚未是完整情境題。開始測驗時，每單元隨機抽取 1–10 個，再由本機模型每次寫兩題繁體中文四選一應用題；檢查具體情境、四個不同選項、答案、解析和可在教材原句核對的引文。不合格輸出最多重試一次；合格題目依知識點快取。這就是首次出題比整理文字知識點慢的原因，所選單元愈多、題數愈大，等待通常愈長。
- **速度與可觀察性**：情境題使用精簡題幹、選項和解析及模型 JSON 模式，減少冗長輸出與無效格式重試；工作進度每寫好一批就更新。完成後顯示從快取取得的題數、模型呼叫次數及產題時間。無法保證真實伺服器的秒數，仍取決於本機模型速度、同時進行的講稿工作和題數。
- **題數與成績**：Scenario Practice 的下拉選單選 **每單元 1–10 題**，按 Enter 或 Start 開始；總題數是「單元數 × 所選題數」。可逐題作答、切換 Previous/Next，按 **Finish & View Results** 交卷。漏答會先確認。結果列出總分、逐單元分數、每題對錯／選項／正解／解析，並持久保存同課程累計測驗次數、題數與正確率。重送同一份交卷不會重複計入。
- **介面與課程管理**：移除測驗課程標題下方多餘的兩行說明。課程選單列出已保存課程、單元數與識別尾碼，方便區分同名上傳。可選擇 **Delete selected course**；需確認且輸入伺服器上的私有刪除碼。刪除整門上傳課程及其 PDF、題庫、測驗資料；內建呼吸生理不可刪，刪掉目前課程後回到內建課程。資料搬移在刪除碼建立之前進行，避免舊課程因新檔案而漏搬。
- **Report 辨識與修正**：回報會保存至 SQLite；寄信設定存在時也排入郵件佇列。明確的正面回報標為 `positive/kept`，不改寫既有答案；太慢標為 `performance/logged`。錯誤、缺漏、看不懂或文風不佳標為 `repair`，依固定指引重新檢索教材、產生候選答案、審查並驗證。通過後相同課程與問題會使用修正版，相近的上傳課程問題可套用經驗證的表達指引。學生留言只用於判斷改善方向，不當作教材事實；若無足夠來源或無可驗證改善，維持原答案並顯示錯誤狀態。`不滿意` 等否定詞不會誤當正面評價。

測驗統計按**課程**累計，沒有學生登入識別，因此不是個別學生的成績單。100 是來源知識點，不是預先寫完 100 道情境題；要求十題、二十八個單元時會有 280 道情境題需要生成，首次仍可能很久。已有快取的題目可免去再次生成。

## 最快部署步驟

先從交付連結下載 ZIP。Windows PowerShell：

```powershell
scp "$env:USERPROFILE\Downloads\NTULUNG_TA_v241_10_QUIZ_REPORT_COURSE_MANAGEMENT.zip" USER@YOUR_SERVER:/path/to/workdir/
ssh USER@YOUR_SERVER
```

登入伺服器後執行：

```bash
cd /path/to/workdir
unzip -o NTULUNG_TA_v241_10_QUIZ_REPORT_COURSE_MANAGEMENT.zip
cd NTULUNG_TA_v241_10_QUIZ_REPORT_COURSE_MANAGEMENT
chmod +x *.sh
./INSTALL_FINAL.sh
curl -fsS http://127.0.0.1:8179/api/health
```

健康檢查應顯示 `v241.10-quiz-report-course-management`；網站為 `https://lungta.twchu.workers.dev/reference/`。安裝器先執行完整預檢，再保留 v241.9 已上傳課程、上傳進度、回報資料庫與郵件設定，啟動新版並部署 Worker。只想檢查時可執行 `VQ_PREFLIGHT_ONLY=1 ./INSTALL_FINAL.sh`。需要刪課程時，在伺服器執行 `cat course_workspaces/.admin_delete_token`，將結果輸入網頁提示框；不要把刪除碼公開。郵件需沿用或設定 `feedback/feedback.env`，沒有設定時 Report 仍會保存並檢查，但不會寄信。

## 測試範圍與限制

執行 `./CHECK_V241_2_ONE_CLICK_STABLE.sh`：驗證前端兩個頁面的題數、交卷摘要、課程刪除介面；後端以合成 PDF 和模擬模型檢查 100 個來源知識點、1 與 10 題邊界、計分持久化與冪等、單課程刪除權限、正面與文風／完整度回報、修正後的回答記憶，以及既有上傳、講稿、聲線和 V/Q 行為。測試不會量到正式機器的 Ollama 產題時間，也無法證實正式郵件已送達；部署後需以真實教材、模型與郵件設定確認。
